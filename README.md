# Mikhlink

## Зачем существует проект

Mikhlink — нативный выходной плагин OBS Studio для Windows и открытый аналог связки Moblin + Moblink. Он должен распределять один поток OBS между несколькими каналами связи, объединять их и отправлять поток на заданный SRTLA-приёмник, прежде всего BELABOX.

Mikhlink не является VPN для всего компьютера: bonding применяется только к передаваемому потоку OBS.

## Целевая схема

- Через меню OBS «Сервис → Mikhlink» указываются имя подключения, ingest key, полный SRT ingest URL и порт SRTLA, после чего активируется служба Mikhlink.
- После активации штатная страница «Настройки → Трансляция» может показывать Mikhlink как текущую службу, но не редактирует её настройки.
- OBS кодирует видео и аудио согласно обычным настройкам вывода пользователя.
- Mikhlink получает готовые кодированные пакеты OBS без повторного кодирования и изменения качества.
- Mikhlink использует одновременно доступные физические соединения Windows: LAN, Wi-Fi и другие аппаратные сетевые адаптеры; виртуальные интерфейсы Hyper-V/WSL не участвуют.
- Основные дополнительные каналы — телефоны с запущенным Moblin в режиме Moblink.
- Каналам можно назначать приоритет или режим использования, например основной, дополнительный или резервный.
- Mikhlink распределяет трафик потока между каналами и сохраняет трансляцию при ухудшении или пропадании отдельного соединения.
- Результат отправляется на настроенный адрес SRTLA/BELABOX.
- Обычный SRT рассматривается как резервный способ передачи.

## Управление в OBS

Штатный список служб OBS жёстко формируется из встроенного каталога и не поддерживает полноценные настройки сторонней службы. Поэтому Mikhlink использует собственное окно настроек.

После сохранения Mikhlink программно назначается текущей streaming service OBS, а запуск и остановка выполняются обычной кнопкой «Запустить трансляцию». Параметры подключения следует изменять только через «Сервис → Mikhlink»: применение штатной страницы «Настройки → Трансляция» может заменить стороннюю службу встроенной службой OBS.

Окно Mikhlink использует язык интерфейса OBS: русский для русской локали и английский для остальных. Ingest key скрывается в поле ввода. Mikhlink извлекает `streamid` из скопированного URL и передаёт его штатному SRT output OBS отдельно, не дублируя секрет в адресе назначения.

Mikhlink принимает оба варианта данных BELABOX:

- готовый URL `srt://host:port?streamid=KEY` — отдельное поле ключа можно оставить пустым;
- URL без `streamid` и отдельно введённый ingest key — Mikhlink передаёт ключ в отдельном параметре SRT;
- если ключ присутствует в обоих местах, значения должны совпадать, иначе сохранение блокируется.

В прямом SRT-режиме используется порт из SRT ingest URL. В тестовом SRTLA-режиме OBS отправляет SRT на локальный sender, а тот подключается к серверу и отдельному SRTLA-порту из настроек.

Для BELABOX Cloud Mikhlink проверяет назначение портов: `4000` — SRT ingest, `4001` — watch URL, `5000` — SRTLA ingest. Watch URL на `4001` нельзя сохранить как адрес публикации.

## Кодирование

По умолчанию Mikhlink использует streaming encoders, выбранные и настроенные в OBS:

- H.264 или H.265/HEVC;
- NVENC, Quick Sync, x264 или другой поддерживаемый OBS энкодер;
- разрешение, FPS, CBR/VBR, битрейт, интервал ключевых кадров, preset, profile и B-frames;
- выбранный аудиокодек, битрейт и аудиодорожку.

Mikhlink не повторяет эти настройки и не перекодирует поток. Полученные пакеты упаковываются в совместимый с SRTLA/BELABOX транспорт и передаются через bonding. Изменение активных настроек кодирования применяется после перезапуска передачи.

## Состояние каналов

Для каждого соединения должны отображаться:

- тип, название и состояние подключения;
- текущая скорость передачи;
- доля трафика или процент использования канала;
- назначенный приоритет;
- для телефона Moblink — заряд батареи и состояние нагрева.

BELABOX является основным тестовым SRTLA-приёмником проекта.

## Интерфейс и оверлеи

- Основная телеметрия отображается в отдельной dock-панели OBS и не входит в видеопоток.
- При необходимости пользователь сможет добавить отдельный настраиваемый источник Mikhlink Overlay в сцену.
- Для стримового оверлея можно будет выбирать показатели, оформление, положение и видимость.

## MVP

- Загружаться как нативный плагин OBS Studio.
- Регистрироваться как служба трансляции и собственный OBS Output.
- Получать кодированные видео- и аудиопакеты от OBS.
- Обнаруживать локальные сетевые адаптеры Windows.
- Подключать телефоны Moblink и получать их телеметрию.
- Передавать поток через несколько соединений.
- Переживать отказ отдельного соединения без остановки трансляции.
- Отправлять объединённый поток на SRTLA/BELABOX.

## Текущее состояние

- Облачная Windows-сборка создаёт `mikhlink.dll`.
- Плагин успешно загружается в OBS Studio 32.1.2.
- Обнаружение адаптеров и состояний Up/Down проверено на реальном компьютере.
- Получение сырых видео- и аудиоданных проверено: 232 кадра и 360 аудиоблоков за 7,756 секунды.
- Получение готового потока из штатных streaming encoders OBS проверено: H.264/AAC, 172 видеопакета и 268 аудиопакетов за 6,329 секунды без повторного кодирования.
- Для проверки реального приёма подключён штатный MPEG-TS/SRT output OBS: Mikhlink передаёт готовый H.264/AAC-поток напрямую в SRT ingest без bonding.
- Прямой SRT ingest BELABOX проверен на реальной трансляции: после автоматического переподключения передача шла со скоростью 5,3 Мбит/с, без retransmit и drop.
- Добавлен первый SRTLA-этап для Windows: поставляемый вместе с DLL sender принимает локальный SRT от OBS, подключается к SRTLA-порту BELABOX и автоматически использует активные IPv4-интерфейсы с default gateway.
- SRTLA bonding проверен на реальной трансляции через два Windows uplink: 86,8 секунды, 71 МБ, средняя скорость 6,5 Мбит/с, `0%` retransmit и `0%` drop. Нагрузка действительно распределялась между адресами примерно как 3,46 + 3,06 Мбит/с.
- Устранено стартовое переподключение после простоя: SRTLA sender теперь запускается непосредственно при начале трансляции, а не во время сохранения настроек.
- Добавлена локальная dock-панель Mikhlink с именами и IP каналов, состоянием, скоростью, долей трафика, RTT и jitter. Панель открывается через «Вид → Док-панели → Mikhlink» и не является источником сцены, поэтому не попадает в трансляцию.
- В dock-панель добавлено ручное управление каждым физическим Windows uplink: режимы «Бондинг», «Резерв» и «Отключён», а также процентный ползунок относительного приоритета от 1 до 100%. Старые значения 1–10 мигрируют автоматически, выбор сохраняется по стабильному идентификатору сетевого адаптера.
- Режим и приоритет можно изменять прямо во время трансляции: Mikhlink атомарно обновляет веса, а SRTLA sender применяет их на служебном тике без разрыва потока и соединений. Отключённый канал остаётся зарегистрированным с весом 0, поэтому его можно вернуть в работу на лету.
- Приоритет реально меняет долю трафика в планировщике SRTLA — это подтверждено проверкой на реальной трансляции. Резервный канал остаётся зарегистрированным с минимальной долей и автоматически принимает поток, если основные bonding-каналы перестают быть доступными.
- Виртуальные адаптеры Windows (включая `vEthernet`, Hyper-V, WSL, VMware, VirtualBox и программные VPN/TAP/TUN) отфильтровываются по типу, имени и описанию и не показываются в dock-панели.

## Текущий этап

Следующий программный этап — подключить Moblink-телефоны как дополнительные каналы и расширить панель их зарядом, температурным состоянием и телеметрией.

## Принятые решения

- Тип продукта: нативный выходной плагин OBS Studio.
- Язык: C++.
- Система сборки: CMake и GitHub Actions с MSVC.
- Первая целевая платформа: Windows x64.
- Настройки кодирования берутся из OBS; отдельное повторное кодирование не выполняется.
- Разработка ведётся небольшими проверяемыми этапами.
- Пустые будущие модули заранее не создаются.

## Компонент SRTLA

Windows-артефакт содержит `srtla_send.exe` из MIT-лицензированного проекта `irlserver/srtla_send`, собранный из зафиксированного commit SHA с Mikhlink-патчем весов uplink-каналов и их live-перезагрузки. Патч хранится в репозитории и автоматически применяется и проверяется в GitHub Actions. `mikhlink.dll`, `srtla_send.exe` и файл лицензии должны находиться вместе в каталоге плагинов OBS.
